# VM4.2 使用与二次开发 FAQ

> 本文件提炼自《VM4.2（应用 & VM SDK 开发）》使用与二次开发 FAQ（PDF 第 387–597 页）。
> 涵盖：常用工具和配置修改、第 1 章 VM 软件使用（环境配置类 / 工具类）、第 2 章 VM 二次开发（环境配置类 / 模块操作类 / 控件嵌入类 / 结果获取类 / 全工具类）。
> 说明：VM4.2 相对 VM4.0 有部分更新，本章仅提供相对 4.0 有更新的内容；与 4.0 重复的通用问题可查阅 4.0 章节。

## 本章速览

1. **普通用户权限运行 VM**：用管理员安装 VM4.2，运行 `Tools\SetNormalUserPermissions.exe` 输入 `S`，并对普通用户（Users）配置安装目录完全控制权限。
2. **联合 OpenCV 开发**：脚本模块添加引用 `OpenCvSharpExtern.dll`，并拷贝到 `Applications\VmModuleProxy\x64` 依赖目录。
3. **规避流程卡死**：加密狗必须直插（禁用 USB 延长线）；不要在全局脚本的"加载结束回调"中调用连续执行接口（会造成界面线程锁死）。
4. **标定类工具**（平移旋转标定 / 旋转标定 / 单点抓取 / 单点纠偏 / 单点映射对位）：适用于单相机+机构场景，标定文件支持 `.xml` / `.iwcal`，刷新信号含义固定。
5. **流程输入/输出/显示**：用流程小扳手配置输出，橘色箭头连线连接流程，再在下游模块订阅输入。
6. **多流程传图**：使用"数据队列"模块（入队类型 IMAGE），配置触发流程；流程内用"发送数据/接收数据"模块。
7. **脚本保存图像**：用 `ImageData` + OpenCV `Mat` + `Cv2.ImWrite`。
8. **全局触发模块动作**（如创建基准）：在 `SinglePointGrabModuAlgorithmTab.xml` 的 Item 下加 `Command` 节点，`SupportCommTrigger=True`。
9. **C# 二次开发环境**：框架 `.NET Framework 4.6.1`、取消"首选 32 位"；用 `ImportRef.exe` 添加引用；WinForm 引用 `VMControls.Winform.Release.dll`，WPF 引用 `VMControls.WPF.Release.dll`。
10. **MFC/Qt 二次开发**：MFC 配置 VC++ 目录 + `iMVS-6000PlatformSDK.lib` + ActiveX 控件；Qt 用 `.pro` 添加外部库并加 `QT +=axcontainer`。
11. **普通用户 EXE 启动 Server**：C# 改 `xxx.exe.config` 的 `AppSettings`（ServerPath）；C++ 调 `SetServerPath()`。
12. **启动报错通用排查**：方案未损坏、加密狗、管理员运行 VS、框架 4.6.1、关闭 VM、补丁后跑 `unGAC.bat`/`GAC.bat`、用 try-catch 抓异常码。
13. **注册表取安装路径**：`HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\VisionMaster_4.2.0` 的 `DisplayIcon`。
14. **第三方库冲突**：Json 版本重定向（13.0.0.0 vs 11.0.0.0）导致格式化界面乱码；MaterialDesign 样式库与 VM 控件字体冲突需重定义 TextBox 样式。
15. **用户日志**：`log4Net.config` + `LogHelper` 类，日志输出到 `exe\user\user.log`。
16. **LabView 二次开发**：必须"浅封装" VM 控件与 `VMOperator` 类库（.NET 容器调用），结束时务必 `DestroyInstance()` 释放，否则 LabVIEW 崩溃。
17. **流程/模块输入图像**：`SetInputImage_V2()` / `GetOutputImageV2()`；Mat/Bitmap 是 BGR，流程输入是 RGB，需交换通道。
18. **模块参数/ROI/图像源**：`ModuParams.SetInputImage()`、`ModuParams.EdgeThresh`、`ModuParams.ModuRoiManager.RoiRectangle`。
19. **SDK 传入图像**：`ImageSourceModuleTool.SetImageData(ImageBaseData)`；VM4.2 像素枚举 `VMPixelFormat`（MONO_08=17301505，RGB24=35127316），VM4.0 用 `ImagePixelFormat`（1/2）。
20. **回调与结果获取**：推荐用流程级输出 `ModuResult.GetOutputInt/Float/String/ImageV2`；可注册单流程 `OnWorkBeginStatusCallBack` / `OnWorkEndStatusCallBack`。

## 第1章 VM 软件使用

### 1.1 环境配置类

### 1.1.1 用户权限：普通用户权限使用VM 的方法

- **问题现象 / 适用场景**：生产现场只部署了普通用户权限，而 VM 需要使用管理员权限，普通用户权限下无法正常启动 VM4.2。
- **解决步骤**：
  1. 管理员权限下，安装 VM4.2.0 安装包。
  2. 打开 VM 安装路径下 `.\Tools\SetNormalUserPermissions.exe`，输入 `S`，按回车键。
  3. 管理员权限下，手动在 VM 安装路径，配置要使用的普通用户（此处为 Users 用户）的"完全控制"权限。此步骤不配置可能导致加载资源失败。
  4. 管理员权限下，关闭防火墙和杀毒软件。此步骤不配置，软件有时会打不开。
  5. （非必要）根据现场情况：需要使用深度学习 GPU 模块的不用配置。管理员权限下，将 `AwakenGpuTool.exe` 删掉，否则有的电脑测试会出现 `cudart64_110.dll` 丢失报错；如不发生此报错无需删除（此工具用于深度学习模块，不影响 2D 算法模块使用，如需使用深度学习模块不需执行步骤 5）。
  6. （非必要）有些电脑打开 VM 时会提示需要输入管理员密码，要在管理员账户下改组策略：点击左下角"Win"图标，搜索处输入 `gpedit.msc` → 确定，打开"本地组策略编辑器"，`计算机配置` → `Windows 设置` → `安全设置` → `本地策略` → `安全选项` → `用户帐户控制：以管理员批准模式运行所有管理员`，改为"已禁用"。
- **关键 API / 类名 / 路径 / 注册表项**：
  - 工具：`VisionMaster4.2.0\Tools\SetNormalUserPermissions.exe`
  - 待删除工具：`AwakenGpuTool.exe`（深度学习 GPU 模块启动工具）
  - 组策略命令：`gpedit.msc`
- **注意事项 / 坑**：步骤 3（目录权限）与步骤 4（防火墙/杀毒）不配置会直接导致启动失败或打不开；非必要步骤按现场是否用深度学习、是否弹管理员密码决定。

### 1.1.2 脚本环境：联合OpenCV 开发的环境配置方法

- **问题现象 / 适用场景**：联合 OpenCV 进行脚本模块开发时，如何配置环境（VM4.2）。
- **解决步骤**：
  1. 给脚本模块添加引用程序集，OpenCV 可以在 VM 安装路径下获取。
  2. 将 VM 安装路径下第三方库中的 `OpenCvSharpExtern.dll` 手动拷贝到脚本依赖目录下，即拷贝到 `D:\VM4.2\VisionMaster4.2.0\Applications\VmModuleProxy\x64` 文件中。
- **关键 API / 类名 / 路径 / 注册表项**：
  - DLL：`OpenCvSharpExtern.dll`
  - 依赖目录：`VisionMaster4.2.0\Applications\VmModuleProxy\x64`
- **注意事项 / 坑**：只添加引用不够，必须把 `OpenCvSharpExtern.dll` 拷贝到 `VmModuleProxy\x64` 才能让脚本运行时找到原生库。

### 1.1.3 环境配置：规避流程运行时卡死的方法

- **问题现象 / 适用场景**：VM4.2 流程运行卡死场景（两类）。
- **解答 / 场景与策略**：
  - **场景 1**：安装 VM4.2 版本，运行久了会出现软件进程卡死，每次卡死都要重启电脑。远程查看后发现后台有两个 server 进程，其中一个进程卡死无法关闭。
    - **解决策略**：加密狗**不能使用 USB 延长线，必须直插**。否则会出现加密狗接口在退出时卡死，造成服务无法退出。
  - **场景 2**：客户在全局脚本设置，VM 加载方案完成后，全局脚本直接触发流程 1 进行连续运行。（1）重启设备设置开机自启动加载方案，偶现全局脚本代码无法触发流程运行；（2）偶现切换方案，主界面卡死无法操作。远程发现客户在全局脚本"加载结束回调"中调用连续执行接口，连续执行会回调信息给界面，与界面线程锁死。
    - **解决策略**：**不要在全局脚本的加载结束回调中调用连续执行接口**，可把连续执行接口写在其它地方。若要达到"加载方案结束后自动触发连续执行"，可在回调里触发一个信号量，由线程监督此信号量控制流程连续执行。
- **关键 API / 类名 / 路径 / 注册表项**：
  - 全局脚本回调：加载结束回调（连续执行接口调用点）
- **注意事项 / 坑**：不正规操作（USB 延长线、回调中调连续执行）会导致进程/界面卡死，属典型"线程锁死"。

### 1.2 工具类

### 1.2.1 平移旋转标定：平移旋转标定模块的使用方法

- **问题现象 / 适用场景**：VM 二次开发如何使用平移旋转标定模块（VM4.2）？
- **适用场景**：单相机与机构（模组/机械手）的标定场景。
- **标定方式**：单相机与机构做平移标定（9 点标定）或平移旋转标定（12 点标定）。前者适用于吸嘴与旋转轴共轴的场景，后者适用于吸嘴与旋转轴不共轴的场景。
- **限制条件**：不支持多相机联立坐标系。
- **模块参数说明**：
  1. **标定类型**：平移标定（九点标定）只需图像点和物理点；平移旋转标定（十二点标定）需要图像点、物理点、图像角度和物理角度。
  2. **标定点获取**：支持"触发获取"及"手动输入"两种方式。触发获取需订阅图像点和机构物理点作为输入参数；手动输入需手动填写图像点及物理点坐标。标定点输入支持"按点"和"按坐标"两种方式。**注意：手动输入模式缺少图像角度，故无法计算旋转一致性和左右手手性。**
  3. **相机模式**：支持相机静止和相机运动两种模式。**自由度**：支持三种自由度，默认仿射模式。
  4. **平移次数**：默认 9 次，可调整（4–16）。**旋转次数**：平移标定自动隐藏；平移旋转标定需手动输入，建议 3 次，可调整（3–16）。
  5. **更新文件**：默认不更新，开启后若进行一次标定，则自动更新指定路径下的标定文件。标定文件路径：设置标定文件保存的路径（保存为 xml 格式）。
  6. **示教（可选项，可关闭）**：开启后，若通讯触发字符与输入的外部触发字符相匹配，则将示教的基准图像坐标、示教点物理坐标、拍照位物理坐标（默认标定中心点坐标，如九点标定则为第五点坐标）保存至标定文件。
- **关键 API / 类名 / 路径 / 注册表项**：
  - 模块名称示例：平移旋转标定模块（配置界面参数如上）
  - 标定文件格式：`.xml`
- **注意事项 / 坑**：手动输入无法算旋转一致性与手性；刷新信号含义见 1.2.3/1.2.5 等"标定文件"小节。

### 1.2.2 旋转标定：旋转标定模块的使用方法

- **问题现象 / 适用场景**：VM 二次开发如何使用旋转标定模块（VM4.2）？
- **适用场景**：单相机与机构（模组/机械手）的旋转中心标定场景。
- **标定方式**：相机静止时，机构带标定物旋转 N 次；相机运动时，机构带相机旋转 N 次，标定机构旋转轴中心坐标。
- **限制条件**：保证运动是纯旋转（无平移），每次旋转角度需严格相等，旋转次数至少为 3 次。
- **模块参数说明**：
  1. **图像点**：图像中特征点的像素坐标。输入支持"按点"和"按坐标"两种方式。
  2. **物理旋转角度**：机构每次旋转的角度值。
  3. **旋转次数**：机构旋转的次数。
  4. **标定文件**（如未加载平移标定文件，则无法标定旋转中心）：加载平移标定文件，支持 `.xml` 和 `.iwcal` 格式。刷新信号填写说明：空或 0 时，表示模块读取标定文件后便不再更新，一直使用第一次读取的标定文件；非零时，表示模块运行时会读取该路径下的标定文件，当该路径下的标定文件发生更新时，模块读取的标定文件就是最新的。
  5. **模块结果**：包括模块状态、剩余标定次数、旋转轴图像点、旋转中心物理点、旋转像素平均误差、旋转真实平均误差。
- **模块结果含义**：
  | 结果项 | 含义 |
  | --- | --- |
  | 模块状态 | 运行成功为 1，运行失败为 0 |
  | 剩余标定次数 | 等于标定总次数减去已运行次数，值为 0 表示旋转标定结束 |
  | 旋转轴图像点 | 旋转轴中心的像素坐标值 |
  | 旋转中心物理点 | 旋转轴中心的物理坐标值 |
  | 旋转像素平均误差 | 拟合平均误差，单位像素 |
  | 旋转真实平均误差 | 拟合平均误差，单位平移标定的物理运动量（通常为 mm） |
- **关键 API / 类名 / 路径 / 注册表项**：
  - 标定文件格式：`.xml` / `.iwcal`
- **注意事项 / 坑**：必须纯旋转且每次角度严格相等；未加载平移标定文件无法标定旋转中心。

### 1.2.3 单点抓取：单点抓取模块的使用方法

- **问题现象 / 适用场景**：VM 二次开发如何使用单点抓取模块（VM4.2）？
- **适用场景**：单相机拍物料的抓取场景。
- **标定方式**：单相机与机构做平移标定（9 点标定）或平移旋转标定（12 点标定）。前者适用于吸嘴与旋转轴共轴；后者适用于吸嘴与旋转轴不共轴。
- **限制条件**：不支持多相机联立坐标系、分离轴抓取、相机拍照位变化（可后接变量计算模块实现）等场景。
- **模块参数说明**：
  1. **输入方式**：确定标定类型是平移标定还是平移旋转标定，确定"按点"还是"按坐标"输入。可订阅前序模块输出结果，也可手动输入。
  2. **像素点**：抓取场景中需依次输入图像基准点和图像运行点。基准像素点输入步骤：输入方式需选"按坐标"（图示为基准点创建成功弹窗、运行点输入步骤）。
  3. **示教抓取物理点**：物料在基准位置时，机构抓取物料的绝对物理坐标。**示教拍照物理点**：物料在基准位置时，机构携带相机拍照的绝对物理坐标。如无需示教抓取物理点、示教拍照物理点，则手动输入 `0`。
  4. **标定文件**：加载本地标定文件，支持 `.xml` 和 `.iwcal` 格式。刷新信号：空或 0 时一直使用第一次读取的标定文件；非零时模块运行时读取该路径下最新标定文件。
  5. **模块结果**：分为相对坐标及绝对坐标，绝对坐标为机构抓取的绝对物理位置。
- **关键 API / 类名 / 路径 / 注册表项**：
  - 标定文件格式：`.xml` / `.iwcal`
- **注意事项 / 坑**：无示教物理点时手动填 0；相机拍照位变化需后接变量计算模块。

### 1.2.4 单点纠偏：单点纠偏模块的使用方法

- **问题现象 / 适用场景**：VM 二次开发如何使用单点纠偏模块（VM4.2）？
- **适用场景**：单相机拍物料的纠偏场景。
- **标定方式**：单相机与机构做平移标定（9 点标定）或平移旋转标定（12 点标定）。（共轴/不共轴适用同上）
- **限制条件**：不支持多相机联立坐标系、分离轴纠偏、相机拍照位变化（可后接变量计算模块实现）等场景。
- **模块参数说明**：
  1. **输入方式**：确定标定类型、按点/按坐标输入；可订阅前序模块或手动输入。
  2. **像素点**：纠偏场景需依次输入图像基准点和图像运行点。基准像素点输入方式需选"按坐标"（图示为基准点创建成功弹窗、运行点输入步骤）。
  3. **示教物理点**：物料在基准位置时的机构绝对物理坐标。如无需示教物理点，则手动输入 `0`。
  4. **标定文件**：加载本地标定文件，支持 `.xml` / `.iwcal`；刷新信号含义同上（空/0 用首次读取，非 0 用最新）。
  5. **模块结果**：分为相对坐标及绝对坐标，绝对坐标为机构纠偏的绝对物理位置。
- **关键 API / 类名 / 路径 / 注册表项**：
  - 标定文件格式：`.xml` / `.iwcal`

### 1.2.5 单点对位：单点映射对位模块的使用方法

- **问题现象 / 适用场景**：VM 二次开发如何使用单点映射对位模块（VM4.2）？
- **适用场景**：上相机拍目标、下相机拍对象的对位贴合场景。
- **标定方式**：上相机到下相机做映射标定，下相机与机构做平移旋转标定（12 点标定）。
- **限制条件**：不支持单相机（循环）对位贴合、上/下相机各自基准对位等场景。
- **模块参数说明**：
  1. **输入方式**：确定按点/按坐标输入；可订阅前序模块或手动输入。
  2. **像素点**：依次输入"对象像素点"和"目标像素点"，输入方式选"按坐标"。给目标像素直线起点/终点的 X、Y 坐标订阅数值（映射后夹角会变化，因此需将目标图像中指定直线映射到对象坐标系再求目标点的角度）。
  3. **示教抓理点**（原文如此，应为"示教抓物理点"）：映射标定时机构反向吸取标定板的绝对物理坐标。如无需示教物理点，则手动输入 `0`。
  4. **标定文件**：映射标定文件将上相机中目标像素映射到下相机的像素坐标系中；N 点标定文件是将下相机的像素坐标映射到机构的物理坐标系中。支持 `.xml` / `.iwcal`；刷新信号含义同上。
  5. **模块结果**：分为相对坐标及绝对坐标，绝对坐标为机构对位的绝对物理位置。
- **关键 API / 类名 / 路径 / 注册表项**：
  - 标定文件格式：`.xml` / `.iwcal`
- **注意事项 / 坑**：目标角度需通过映射后直线求得，不能直接用原图像角度。

### 1.2.8 脚本模块：脚本模块保存图像的方法

- **问题现象 / 适用场景**：如何使用脚本模块保存前序模块传入的图像（VM4.0 及以上）？
- **关键代码**（C#，脚本模块 `Process()`）：
```csharp
public bool Process()
{
    ImageData DetImg = new ImageData();
    GetImageValue("DetImg",ref DetImg);
    byte[] bytes = new byte[1024 * 1024];
    bytes = DetImg.Buffer;

    int wid = DetImg.Width;
    int hei = DetImg.Heigth;
    Mat src = new Mat();
    if (ImagePixelFormate.MONO8 == DetImg.PixelFormat)
    {
        int dataLen = wid * hei;
        src.Create(hei, wid, MatType.CV_8UC1);
        Marshal.Copy(DetImg.Buffer, 0, src.Ptr(0), dataLen);
    }
    else if (ImagePixelFormate.RGB24 == DetImg.PixelFormat)
    {
        int dataLen = wid * hei * 3;
        src.Create(hei, wid, MatType.CV_8UC3);
        Marshal.Copy(DetImg.Buffer, 0, src.Ptr(0), dataLen);
        Cv2.CvtColor(src, src, ColorConversionCodes.RGB2BGR);
    }
    string savePath = "E:\\Test";   // 存图路径
    string imageName = "1.jpg";   // 存图名称
    if (!Directory.Exists(savePath))
    {
        Directory.CreateDirectory(savePath);
    }
    Cv2.ImWrite(savePath + "\\" + imageName, src);
    src.Release();
    return true;
}
```
- **关键 API / 类名 / 路径 / 注册表项**：
  - 类/枚举：`ImageData`、`ImagePixelFormate.MONO8` / `RGB24`、`Mat`、`MatType`、`Cv2`、`Marshal`
  - 接口：`GetImageValue("DetImg", ref DetImg)`
- **注意事项 / 坑**：`DetImg.Heigth` 为原文拼写（Height 笔误），代码需按实际 SDK 修正；RGB 需转 BGR 后再 `ImWrite`。

### 2.1.5 环境配置：程序启动后报错的通用方法

- **问题现象 / 适用场景**：二次开发中常遇到启动后直接报错 `VM.Core.xxxx` 类型初始值设定引发异常、控件黑色、模块报错、加载方案报错、获取不到流程列表、流程和结果为空等（VM4.2 + VS2013 及以上）。

### 2.1.6 VM 路径：通过注册表获取VM 安装路径的方法

- **问题现象 / 适用场景**：如何后台自动获取 VM 的安装路径（VM4.0 及以上 + VS2013 及以上）？
- **关键代码（C#）**：
```csharp
//从注册表读取VM 安装路径
public string GetVisionMasterInstallPath()
{
    try
    {
        RegistryKey Key = RegistryKey.OpenBaseKey(RegistryHive.LocalMachine, RegistryView.Registry64);
        RegistryKey myreg = Key.OpenSubKey(@"SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\VisionMaster_" + "4.2.0", RegistryKeyPermissionCheck.Default, System.Security.AccessControl.RegistryRights.FullControl);
        string VisionMasterInstallPath = myreg.GetValue("DisplayIcon").ToString();
        Key.Close();
        myreg.Close();
        return VisionMasterInstallPath.Replace("Applications\\VisionMaster.exe", "");
    }
    catch (System.Exception ex)
    {
        throw ex;
    }
}
```
- **关键 API / 类名 / 路径 / 注册表项**：
  - 注册表项：`HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\VisionMaster_4.2.0`
  - 值：`DisplayIcon`（指向 `Applications\VisionMaster.exe`）
  - 类：`RegistryKey`、`RegistryHive.LocalMachine`、`RegistryView.Registry64`
- **注意事项 / 坑**：需按版本改 `VisionMaster_4.2.0`；读的是 64 位注册表视图（WOW6432Node）。

### 2.1.7 第三方库：格式化模块参数配置界面乱码的解决方法

- **问题现象 / 适用场景**：二次开发时，格式化配置界面乱码或无法打开脚本、变量计算、全局脚本配置界面（VM4.0 + VS2013 及以上）。
- **解答**：

  2. **解决办法**：找 `13.0.0.0` 版本的 Json 库拷贝到二次开发 exe 同级目录，使 VM 和第三方库都自动引用该版本 Json 库。
- **关键 API / 类名 / 路径 / 注册表项**：
  - 配置文件：`App.config`（Json 版本重定向）
  - 第三方库：`HslCommunication.dll`
  - Json 版本：VM 默认 `11.0.0.0`，冲突重定向到 `13.0.0.0`
- **注意事项 / 坑**：将 `13.0.0.0` 的 Json 放到 exe 同级目录即可统一。

### 2.1.8 第三方库：控件与三方样式库冲突问题解决方法

- **问题现象 / 适用场景**：VM 二次开发时，`VmMainViewConfigControl` 或 `VmParamsConfigControl` 控件与自身引用的第三方 `MaterialDesign` 样式库冲突，导致 VM 控件中字体显示异常（VM4.0 及以上 + VS2013 及以上）。原因猜测：VM 控件未对 TextBox 的 FontSize 设置，导致引用 MaterialDesign 样式库时样式覆盖 VM 控件相应样式。
- **解答（三种方案 + 最终办法）**：
  - **方法 1**：VM 修改相关控件样式以避免冲突。但因不同三方库可能引发不同位置冲突，无法解决开发者根本问题。
  - **方法 2**：修改 MaterialDesign 样式库中相关样式。用反编译工具找到该样式库资源文件夹下的 `TextBoxBase` 样式设置，但发现反编译出的样式库无法对资源文件样式修改，行不通。
  - **方法 3**：改变对 MaterialDesign 样式库的引用方式（仅在需要使用该样式的用户控件中引用），但需对 VM 控件及其他控件做隔离，改动太大不实用。
  - **最终解决办法**：在自定义用户控件中对 `TextBox` 的相关样式重新定义，覆盖掉 MaterialDesign 库中引发冲突的部分。

### 2.1.9 用户日志：用户日志打印的方法

- **问题现象 / 适用场景**：VM SDK 开发时如何打印用户日志（VM4.0 + VS2013 及以上）？
- **解答**：
  1. 配置日志 xml，命名为 `log4Net.config`，放在 exe 同级目录：
```xml
<?xml version="1.0" encoding="utf-8" ?>
<configuration>
  <configSections>
    <section name="log4net" type="log4net.Config.Log4NetConfigurationSectionHandler, log4net"/>
  </configSections>

  <log4net>
    <appender name="RollingLogFileAppender" type="log4net.Appender.RollingFileAppender">
      <!--日志路径-->
      <param name="File" type="log4net.Util.PatternString" value=".\user\user.log"/>
      <!--是否是向文件中追加日志-->
      <param name="AppendToFile" value="true"/>
      <!--编码-->
      <param name="Encoding" value="utf-8" />
      <!--log 保留天数-->
      <param name="MaxSizeRollBackups" value="5"/>
      <!--日志文件名是否是固定不变的-->
      <param name="StaticLogFileName" value="false"/>
      <!--日志文件名格式为:2008-08-31.log-->
      <param name="DatePattern" value="yyyy-MM-dd&quot;.log&quot;"/>
      <!--日志根据日期滚动-->
      <param name="RollingStyle" value="Size"/>
      <param name="MaximumFileSize" value="10MB"/>
      <!--多进程同时写入时加锁-->
      <lockingModel type="log4net.Appender.FileAppender+MinimalLock" />
      <layout type="log4net.Layout.PatternLayout">
        <!-- <param name="ConversionPattern" value="%d [%t] %-5p %c - %m%n %loggername" /> -->
        <!--<conversionPattern value="Time：%date ThreadID:[%thread] Level：%-5level MSG：%message%newlineNUM：%-5L FILE：%F%newline" />-->
        <conversionPattern value="%date{yyyy-MM-dd HH:mm:ss.fff} %-5level [%thread] [%class::%method@%L] %message%newline%newline" />
      </layout>
      <filter type="log4net.Filter.LoggerMatchFilter">
        <loggerToMatch value="UserLog" /><!--过滤器-->
      </filter>
      <filter type="log4net.Filter.DenyAllFilter" />
    </appender>

    <root>
      <!--(高) OFF > FATAL > ERROR > WARN > INFO > DEBUG > ALL (低) -->
      <level value="info" />
      <appender-ref ref="RollingLogFileAppender"/>
      <appender-ref ref="UserRollingLogFileAppender"/>
    </root>
  </log4net>
</configuration>
```
  2. 生成用户日志类别，读取 `log4Net.config` 文件：
```csharp
using log4net;
using log4net.Appender;
using System;
using System.Collections.Generic;
using System.Linq;
using System.Reflection;
using System.Text;
using System.Threading.Tasks;

namespace VMTestB3
{
    public class LogHelper
    {
        public static readonly ILog objLog = null;
        static LogHelper()
        {
            try
            {
                string stmp = Assembly.GetExecutingAssembly().Location;
                stmp = stmp.Substring(0, stmp.LastIndexOf('\\') + 1);
                string path = stmp + "log4Net.config";
                log4net.Config.XmlConfigurator.ConfigureAndWatch(new System.IO.FileInfo(path));
                objLog = log4net.LogManager.GetLogger("UserLog");
            }
            catch (Exception ex)
            {
                //程序异常
            }
        }
        public void Info(object message)
        {
            objLog?.Info(message);
            //objLog?.Error(message);
        }
    }
}
```
  3. 在主函数中调用，打印日志到 `项目生成路径\user\user.log`：
```csharp
LogHelper loguser=new LogHelper();
loguser.Info("加载方案.............................................");
VmSolution.Load(textBoxSolPath.Text, "");
```
- **关键 API / 类名 / 路径 / 注册表项**：
  - 配置文件：`log4Net.config`（exe 同级）
  - 类：`log4net`、`LogHelper`、`XmlConfigurator.ConfigureAndWatch`、`LogManager.GetLogger("UserLog")`
  - 日志路径：`exe\user\user.log`
- **注意事项 / 坑**：过滤器 `LoggerMatchFilter` 匹配 `UserLog`；`RollingStyle=Size` 与 `MaximumFileSize=10MB` 控制滚动。

### 2.1.10 环境配置：基于LabView 二次开发环境配置方法

- **问题现象 / 适用场景**：基于 LabView 如何进行 VM 二次开发环境配置（VM4.2 + LabVIEW 2015）？
- **1 预备知识（LabVIEW 调用第三方库方式）**：
  - **1.1 调用库函数方式**：程序面板右击"互连接口"→"库与可执行程序"→"调用库函数节点"→配置，选 DLL 与函数（如 `MVRenderPlus.dll`、旧版 `imvs6000-PlatformSDK.dll` 的 `LoadSolution` 等 API）。适合调 C/C++ 独立动态库，但调用者需掌握 C 与头文件。
  - **1.2 ActiveX 容器方式**：对 COM 标准动态库方便。以 `VmMainView` 控件为例，选"打开自动化"→浏览 `VmMainViewControlWinform Version 1.0`→创建 `VmMainViewControlInterface` 引用→"调用节点"→`GetObjectPointer` 等。

- **2 遇到的困境**：
  - 困境 1：选 GAC 列表中的 VM 控件库无反应（.NET 容器插入 `VMControls.Winform.Release` 的 `VmMainViewConfigControl` 后前面板无变化）。
  - 困境 2：改选安装目录 `C:\Program Files\VisionMaster4.2.0\Development\V4.x\ComControls\Libraries\win64` 下的 dll，报"尝试加载程序集时发生错误"。
- **3 解决办法**：正确加载 `VM.Controls.Winform.Release` 需将 VM 控件做成"用户自定义控件"（浅封装），由 LabVIEW 加载用户自定义控件，避免 LabVIEW 自动初始化控件时异常被 SDK 吞掉。

  - **第 2 步**：VS 工具箱添加 VM 控件（如 `VmMainViewConfigControl`）到用户窗体，设 `Dock=Fill`（适应宿主窗口、可拖动改大小）。

### 2.2.1 流程操作：通过流程或Group 设置输入输出图像的方法

- **问题现象 / 适用场景**：二次开发中如何设置流程输入输出图像（VM4.2 + VS2013 及以上）？
- **解答**：可打开流程配置窗口，将流程 1 输出图像设为流程 2 输入图像（VM 中可连线实现，也可用代码）。通过 Group 设置输入输出图像也调用同样的 `SetInputImage_V2()` / `GetOutputImageV2()`。注意：用代码给流程输入图像时，流程中其它模块的图像输入源需订阅流程的图像参数；Mat/Bitmap 彩色图转流程输入时，Mat/Bitmap 是 BGR，流程输入图像是 RGB，通道需交换。
- **关键代码（C#）**：
```csharp
VmProcedure process = (VmProcedure)VmSolution.Instance["流程1"];
InputImageData vmImageData = new InputImageData();
//获取流程1 输出图像
ImageBaseData_V2 image = process.ModuResult.GetOutputImageV2("out2");
//设置流程2 输入图像
VmProcedure vmProcedure = VmSolution.Instance["流程2"] as VmProcedure;
vmProcedure.ModuParams.SetInputImage_V2("ImageData", image);
```
- **关键 API / 类名 / 路径 / 注册表项**：
  - 接口：`VmProcedure.ModuResult.GetOutputImageV2()`、`VmProcedure.ModuParams.SetInputImage_V2()`
  - 类型：`InputImageData`、`ImageBaseData_V2`
- **注意事项 / 坑**：BGR↔RGB 通道交换；下游模块需订阅流程图像参数。

### 2.2.2 模块操作：设置输入图像、参数和ROI

- **问题现象 / 适用场景**：VM SDK 二次开发中，如何设置指定模块的输入图像、模块参数及 ROI 区域（VM4.2 + VS2013 及以上）？
- **解答**：一个 VM 模块输入含：基本参数（图像输入、ROI 区域）、运行参数。以圆查找为例。
  - **注意**：设置输入参数（基本参数），参数配置窗口界面不会显示所设参数，此时模块运行参数永久有效，流程运行参数一次有效；设置运行参数，界面会显示所设参数，模块和流程运行参数都永久有效。
  1. **设置模块输入图像**（圆查找，命名空间 `IMVSCircleFindModuCs`）：
```csharp

inputImageData.Names.HeightName = "InImageHeight";//默认InImageHeight
inputImageData.Names.WidthName = "InImageWidth";//默认InImageWidth
inputImageData.Names.PixelFormatName = "InImagePixelFormat";//默认InImagePixelFormat
inputImageData.Data = mat.Data;
inputImageData.DataLen = (uint)(mat.Width * mat.Height);
inputImageData.Height = mat.Height;
inputImageData.Width = mat.Width;
inputImageData.Pixelformat = ImagePixelFormat.IMAGE_PIXEL_FORMAT_MONO8;
IMVSCircleFindModuTool circleFindModuTool = VmSolution.Instance["流程1.圆查找1"] as IMVSCircleFindModuTool;//实例化指定的模块工具

```
  2. **设置指定模块运行参数**（圆查找，设 `ModuParams` 属性）：

  3. **设置指定模块的 ROI 区域**：

  - 命名空间/类：`IMVSCircleFindModuCs`、`IMVSCircleFindModuTool`、`InputImageData`、`ImagePixelFormat.IMAGE_PIXEL_FORMAT_MONO8`、`RectBox`、`VM.PlatformSDKCS.PointF`

```csharp
VMControls.WPF.TextEx text = new VMControls.WPF.TextEx("欢迎使用VM4.2 二次开发！", new System.Windows.Point(1000, 1000), fontSize: 20, stroke: "#FF0000");

```

  - 引用：`VMControls.WPF.dll`、`WindowsBase.dll`（于 `VisionMaster4.2.0\Development\V4.x\ComControls\Assembly`）
- **注意事项 / 坑**：VM4.2 用 `AddShape` 不要在回调加延时；先绑定图像再 AddShape。

### 2.3.9 图像传入：给渲染控件传入图像的方法

- **问题现象 / 适用场景**：VM 二次开发如何将在渲染控件上显示本地图像（VM4.0 及以上 + VS2013 及以上）？
- **解答**：
  1. 可通过模块方式，再将渲染控件绑定模块/流程显示本地图像；也可通过 `VmRenderControl` 控件的 `ImageSource` 属性设置图像。
  2. 首先继承 `IImageData` 接口实现图像数据类：
```csharp
public class ImageSource : VMControls.RenderInterface.IImageData
{
    public ImageSource(int width, int height, byte[] buffer, VMPixelFormat pixelformat)
    {
        Width = width;
        Height = height;
        PixelFormat = pixelformat == VMPixelFormat.VM_PIXEL_MONO_08 ? "Gray8" : "Rgb24";
        int channels = pixelformat == VMPixelFormat.VM_PIXEL_MONO_08 ? 1 : 3;
        if (buffer.Length != width * height * channels)
            throw new Exception("buffer is error");
        Buffer = new byte[buffer.Length];
        Array.Copy(buffer, Buffer, buffer.Length);
    }

    public int Width { get; set; }
    public int Height { get; set; }
    public byte[] Buffer { get; set; }
    public string MemoryAddress
    {
        get
        {
            GCHandle gCHandle = GCHandle.Alloc(Buffer, GCHandleType.WeakTrackResurrection);
            IntPtr bufferAddress = GCHandle.ToIntPtr(gCHandle);
            return bufferAddress.ToString();
        }
    }
    public string PixelFormat { get; }
}
```
  3. 使用 OpenCV 获取本地图像数据流并转成 `ImageSource` 显示：
```csharp
private void button1_Click(object sender, EventArgs e)
{

    if (openFile.ShowDialog() == DialogResult.OK)
    {
        pictureBox1.Image = Image.FromFile(openFile.FileName);
        var mat = Cv2.ImRead(openFile.FileName);
        byte[] imageByte = new byte[mat.Width * mat.Height * mat.Channels()];
        ImageSource imageSource = null;
        if (mat.Channels() == 1)
        {
            imageSource = new ImageSource(mat.Width, mat.Height, imageByte, VMPixelFormat.VM_PIXEL_MONO_08);
        }
        else
        {
            //OpenCV 为BGR VM 为RGB 通道
            Cv2.CvtColor(mat, mat, ColorConversionCodes.BGR2RGB);
            Marshal.Copy(mat.Data, imageByte, 0, imageByte.Length);
            imageSource = new ImageSource(mat.Width, mat.Height, imageByte, VMPixelFormat.VM_PIXEL_RGB24_C3);
        }
        if (imageSource != null)
            vmRenderControl1.ImageSource = imageSource;
    }
}
```
- **注意事项**：灰度图读取到三通道需先转单通道；彩色图需交换 R/G 通道（用 `Cv2.CvtColor` 转一下）。
- **关键 API / 类名 / 路径 / 注册表项**：
  - 接口：`VMControls.RenderInterface.IImageData`、`vmRenderControl1.ImageSource`
  - 枚举：`VMPixelFormat.VM_PIXEL_MONO_08`（→ "Gray8"）、`VM_PIXEL_RGB24_C3`（→ "Rgb24"）
- **注意事项 / 坑**：OpenCV 为 BGR，VM 为 RGB，需 `BGR2RGB`。

### 2.5.4 全局通信：接收和发送数据的方法

- **问题现象 / 适用场景**：二次开发中，全局模块控件中的通信管理如何接收和发送数据（环境：VM4.0 + VS2015 及以上）？

- **关键代码（C#）**：
```csharp
CommManagerModuleTool commTool = (CommManagerModuleTool)VmSolution.Instance["通信管理1"];
if (null != commTool)
{
    commTool.SetString(2, "abcd"); // 发送字符串型数据
    int[] aIntVal = new int[3];
    aIntVal[0] = 10;
    aIntVal[1] = 11;
    aIntVal[2] = 12;
    commTool.SetInt(1, aIntVal, 0); // 发送整型数据
    byte[] btData = null;
    commTool.GetReadData(2, ref btData);//接收数据
}
```
  2. 通过回调接收数据：
```csharp
//注册回调函数，通讯接受事件回调
VmSolution.OnCommunicationRecvCallBackEvent += VmSolution_OnCommunicationRecvCallBackEvent;
private void VmSolution_OnCommunicationRecvCallBackEvent(ImvsSdkDefine.IMVS_COMMU_REPORT_DATA_INFO reportDataInfo)
{
    string strMsg;
    try
    {
        int nType = reportDataInfo.nType;
        byte[] btarr = ExternalCallHelper.IntPtr2Bytes(reportDataInfo.pData, reportDataInfo.nLen);
        int len = btarr.Length;
        string ID = btarr[0].ToString();
        byte[] vs = new byte[len - 2];
        Array.Copy(btarr, 2, vs, 0, len - 2);
        string ReceiveData = System.Text.Encoding.Default.GetString(vs);//数据
        strMsg = ID + "号设备接受到：" + ReceiveData;
    }
    catch (VmException ex)
    {
        strMsg = "读取通信数据失败. Error Code: " + Convert.ToString(ex.errorCode, 16);
    }
}
```
  3. 发送字符串数据同样用 `commManagerModule.SetString()` 接口：
