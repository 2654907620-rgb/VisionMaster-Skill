## 速览

2. 安装 VM4.2 后，旧版本（如 VM4.0）算子会被自动备份到 `V3.4` 文件夹，是版本切换的前提。

7. 卸载 VM4.2 时注意：取消勾选「加密狗驱动、相机 SDK」，再手动重装 VM4.0 算子包（MVSAlgorithmSDK_STD.exe）。

### 4.1 多版本间切换及二次开发程序升级

**说明 / 适用场景**
- 环境：VM4.2 + VS2013 及以上。
- 现象：电脑已安装 VM4.0 或 VM4.1，再安装 VM4.2 后存在两个及以上 VM 版本，客户有「版本间切换」需求，或需将 VM4.0/4.1 的二次开发程序升级到 VM4.2。
- 说明：VM4.2 起提供了版本切换与二次开发升级工具（老版本无对应工具）。VM4.1 的二次开发程序升级操作与 VM4.0 相同。

**要点**

1. **版本安装（算子自动备份）**：安装完 VM4.0 后再装 VM4.2，算子默认装在 C 盘，安装程序会自动备份 VM4.0 的算子。例如 `V3.4` 文件夹即备份 VM4.0 算子的目录，**有此备份文件夹才能进行版本间切换**。
2. **版本间切换**：使用版本切换工具，工具启动后根据注册表查找已安装版本，按需切换。切换前需关闭 VM 后台程序和 Visual Studio。从 VM4.2 切回 VM4.0 时，算子路径会：把 VM4.0 算子从 `V3.4` 拷出、把 VM4.2 算子打包进 `V4.2` 文件夹。多版本无法定位 VM 问题时，也可点【清除配置】再点相应版本。
3. **二次开发程序升级（C#）**：
   - 先用工具备份项目 `debug` 文件夹内容（VM4.2 二次开发不再需要拷贝 VM 提供的二次开发 dll，所以要清空项目生成路径 debug 并将这些 dll 备份到另一文件夹）。
   - 再用引用工具为程序重新添加引用。
4. **方案、流程升级**：程序升级成功后，启动 VM4.2 二次开发程序加载旧方案会报错。需用 VM4.2 打开 VM4.0 搭建的方案/流程做一次升级，成功后有提示窗口，另存为 `xxx_V4.2.sol` 等；个别模块、参数或全局变量需检查并微调。
5. **注意事项**（见下）。

**关键命令 / 路径 / 配置项**

| 用途 | 路径 / 项 |
|---|---|
| 版本切换工具 | `VisionMaster4.2.0\Applications\Tools\VersionSwitchAssistant\VersionSwitchAssistant.exe` |
| 4.0→4.2 二次开发程序升级（备份 debug DLL） | `VisionMaster4.2.0\Applications\Tools\4.0 二次开发程序升级4.2 版本工具\DevelopProcedureUpgradeTool.exe` |
| 二次开发引用工具（添加引用） | `VisionMaster4.2.0\Development\V4.x\ComControls\Tool\ImportRef.exe` |
| 算子包（卸载 VM4.2 后重装 VM4.0 算子用） | `VisionMaster4.x\Drivers\MVSAlgorithmSDK_STD.exe` |
| 旧版本算子备份文件夹 | `V3.4`（备份 VM4.0）；`V4.2`（当前版本算子） |
| 版本定位依据 | 注册表（切换工具据此查找已安装版本） |
| 方案另存命名 | `xxx_V4.2.sol` |

**注意事项**

1. VM4.x 二次开发程序启动前提：VM4.x 能正常打开且方案能正常运行；随后关闭 VM 后台程序，再启动二次开发程序。
2. VM4.2 部分二次开发接口名称有变化，基本兼容 VM4.0 接口，但推荐使用程序中提示的推荐接口（例如获取流程结果需修改代码）。
3. 若将 VM 控件封装在项目1、项目2 再调用项目1，则项目1 也需做二次开发程序升级。
4. 装 VM4.0 再装 VM4.2 后，4.0 算子被备份；若卸载 VM4.2，算子路径会清空 VM4.2 算子及 VM4.0 备份算子，导致 VM4.0 无法使用。想保留 VM4.0，应在卸载 VM4.2 时**不勾选「加密狗驱动、相机 SDK」**，再手动安装 VM4.0 算子包（`VisionMaster4.x\Drivers\MVSAlgorithmSDK_STD.exe`）。
5. C++ 二次开发程序不拷贝 DLL，除更改包含目录和库目录路径外，还需删除项目 exe 生成路径下 VM 相关 dll。
6. 版本切换和升级是 VM4.2 新增功能；VMSDK 程序升级步骤主要针对 VM4.0 与 VM4.1 的二次开发程序。

**问题根因**：不熟悉多版本间切换及二次开发程序升级。

### 5.1 VM 问题采集助手：VM 应用和开发问题排查及异常收集工具

**说明 / 适用场景**
- 一款集多项功能于一体的排查工具，帮助客户快速定位和修复**环境类问题**，降低非代码类、功能性问题的沟通成本，提高排查效率。
- 流程：① 检测 VM 安装环境或 VM SDK 开发环境是否正常，提供一键修复；② 若仍无法解决，调整日志等级（一般到 Debug）以打印更详细日志；③ 收集日志压缩包（系统/软件版本信息、VM 日志、算子日志、dump 文件等）反馈研发。
- **适用版本**：VM4.0 及以上；其中**日志调整功能适用 VM4.2 及以上**。

- 反馈要求：将日志压缩包、问题现象、出问题时间点及时反馈研发，以防日志被覆盖。

**要点**

1. **软件说明**：见上（环境与日志一键检测/修复/收集）。
2. **VM 环境检测**：检测 VM 版本、VM 系统环境变量、用户权限、python 版本、加密驱动、相机驱动、软件运行依赖库、算子版本等。
3. **SDK 引用**：给出 VM SDK 程序报错排查步骤；安装 VM 补丁后建议点【确认更新】，等待更新后的弹出提示。
4. **日志调整**：无法定位原因时调日志等级（一般 Debug）。VM4.2 及以上可自动调整，其它版本需手动加文件（详见下）。
5. **日志收集**：VM 应用问题勾选「VM 应用问题日志」；VM SDK 问题勾选「VM SDK 问题日志」，可据提示选 exe 生成路径文件夹。勾选 VMSDK 问题日志会默认同时收集 VM 日志与 exe 生成路径下日志；算法 SDK 开发问题只需手动收集算子日志。

**关键命令 / 路径 / 配置项**

| 版本 | 位置 | 调整方式（建空文件/文件夹，去掉 .txt 后缀；还原即删除） |
|---|---|---|
| VM4.2 | `\Applications` | 增加文件 `sdk_log_d` |

VM 应用问题需收集的信息：

- 算子日志：`C:\Windows\Temp\MVDSDKLog` 文件夹
- 系统信息：工具自动收集到 `BaseInfo.txt`
- 系统日志：工具自动收集到 `SystemEventLog.txt`

VM SDK 问题需收集的信息（在应用问题基础上额外）：
- VMSDK 日志：项目 exe 生成路径同级目录的 `log` 文件夹和 dump 文件，工具收集到 `Development` 文件夹。

### 5.2 定位精度评估助手：定位精度评估及误差分析工具

**说明 / 适用场景**

- 下载链接：`https://drive.ticklink.com/hcs/controller/hik-manage/fileDownload?link=ZcKDXpwK`

**要点**

1. **软件说明**：见上。
2. **功能说明 — 2.1 精度评估**：评估视觉定位系统各部分精度及整体精度。操作步骤：
   1) 加载标定文件（平移旋转标定文件 / 框架标定文件，`.xml` / `.iwcal` 格式）；
   2) 查看标定文件检查结果，初步确定旋转一致性及手性一致性是否正常；
   3) 做相机静态测试，验证相机及图像算法精度（初始值为参考值，以实际测试为准）；
   4) 做机构动态测试，验证机构精度；
   5) 做机构旋转测试，验证机构旋转精度；
   6) 进行机构示教，填写示教引入误差；
   7) 点击「开始评估」，评估系统最终精度。
   - 精度评估结果以物理值和像素值的参考范围给出（演示效果见原文图示，文字缺失）。
3. **功能说明 — 2.2 问题查找页面**：根据精度评估界面结果做误差排查优化，哪方面误差大按检测项优先优化。步骤：
   1) 选择偏差范围（小偏差 / 大偏差）；
   2) 选择定位引导场景；
   3) 按步骤进行误差排查；
   4) 根据提示操作排查优化，完成项目可标记记录。
   - 所有检测项完成后，视觉定位精度应能达到要求。

**关键命令 / 路径 / 配置项**
- 标定文件格式：`.xml`、`.iwcal`
- 下载：`https://drive.ticklink.com/hcs/controller/hik-manage/fileDownload?link=ZcKDXpwK`

# 三、第4章尾部（HALCON 联合开发收尾 / 异常处理）

> 覆盖范围：4.3.1 联合 HALCON 开发收尾（算子封装 Process 函数、输入获取、输出设置、调试、版权声明）+ 4.4 异常处理（4.4.1 v120 生成工具缺失）。

## 速览

1. 算子封装绝大部分工作量在 `Process` 函数：从 `modu_input` 取输入图像，转成 HALCON 的 `HImage` 后调用 HALCON 算子处理。

### 4.4 异常处理

#### 4.4.1 环境配置：运行算子模块 Demo 时，无法找到 v120 的生成工具

**说明 / 适用场景**
- 环境：VM4.0 及以上 + VS2017。
- 现象：运行算子模块 Demo 时，报错提示「无法找到 v120 的生成工具」。

**要点**

1. **根因**：算子模块自动生成的代码环境是 **VS2013**（平台工具集 v120），在 VS2017 中打开会因缺少 v120 工具集而报错。
2. **解决方式一**：下载安装 VS2013，获取 v120 生成工具。
3. **解决方式二（推荐）**：直接升级生成工具（平台工具集）：
   1) 右击项目名称 → 属性 → 打开项目属性页，将**平台工具集**改成当前 VS2017 对应的 **v141**。
   2) 右击项目名称 → **重定向项目** → 选择相应的 SDK 版本。

**关键命令 / 路径 / 配置项**

| 项 | 值 |
|---|---|
| 报错工具集 | v120（VS2013） |
| 目标工具集 | v141（VS2017） |
| 操作入口1 | 项目属性 → 常规 → 平台工具集 |
| 操作入口2 | 右击项目 → 重定向项目 → 选择 SDK 版本 |

**关键代码**：（无）

**注意事项**：推荐采用升级平台工具集方式，避免额外安装旧版 VS。

**问题根因**：不熟悉如何升级 VS 工具集。
