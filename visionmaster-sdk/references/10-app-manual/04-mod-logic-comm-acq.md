# VM 模块参考：采集 · 通信 · 逻辑工具 · 拆分组合

> 本文件为「模块使用参考」中 **采集 / 拆分组合 / 逻辑工具 / 通信** 四大类的蒸馏版，重点保留**参数含义、取值范围、默认/枚举选项、脚本与 SDK 联动口子**。SDK 文档不覆盖这一层界面配置信息，本文与之互补。
>
> 约定：像素格式枚举值 `Mono8 = 17301505`、`RGB24 = 35127316`；模块状态 `0=NG（红色）`、`1=OK（绿色）`；耗时单位为 ms。

---

## 速览

1. **图像来源三选一**：图像源支持「本地图像 / 相机 / SDK」三类输入；本地图像最多缓存 5 张、方案存图最多 120 张。
2. **拼接能力**：图像源开启「拼接使能」后，按 `起始高度(0~20000)` + `拼接高度(0~20000)` 在 Y 方向拼接上一张缓存图与本次图（相机/SDK 同源参数）。
3. **多图采集**固定输出 3~8 张图，配合多图融合；相机模式可联动曝光、增益、光源通道与触发时间。
4. **输出图像**负责存图：存图使能 + 触发保存（`全部保存/OK时保存/NG时保存/不保存`）、FTP 上传、最大保留 500 天、格式 `BMP/JPEG/PNG`。
5. **缓存图像**最多 15 张（输出 `输出图像*`，`*代表 0~14`），按时间顺序覆盖，用于调试回溯。
6. **光源模块**控制照明：`触发时间(ms)` 范围 `-1 ~ 65535`（-1 常亮）；通道亮度 `0~100`（视觉控制器）/ `0~255`（光源控制器）。
7. **拆分组合**里 Box 三件套：Box融合（按重叠率/中心距合并）、Box重叠率计算（结果 `[0,1]`）、Box过滤（按掩膜内 255 占比过滤，推荐放在多标签筛选后）。
8. **分支判断四件套**：条件分支、条件检测、`分支模块（仅 int）`、`分支字符（string）`，控制流程是否继续及走哪条分支。
9. **逻辑模块**支持 `AND / OR / NOT / NAND / NOR` 综合多模块状态。
10. **格式化模块**把数据整合成字符串，支持「插入文本 / 插入订阅 / 插入数组」，数组支持 `分隔符`、`数组下标（* 或 int）`、`数组列表`。
11. **脚本 = 标准 C#（Windows）**；**Python脚本 = Python**；两者都只处理流程内数据，跨流程批量逻辑用全局脚本。
12. **脚本开放接口核心**：`Init` / `Process`、`GlobalVariableModule.SetValue/GetValue`、`CurrentProcess.GetModule(...).GetValue/SetValue`、`SendData`、`GetIntValue/SetIntValue` 等系列、`ShowImage/DrawShape/ConsoleWrite/ShowMessageBox`。
13. **脚本直接发通信**：`GlobalCommunicateModule.GetDevice(int deviceID).SendData(data)`（TCP/UDP/串口）或 `.GetAddress(int addressID).SendData(data, DataType)`（PLC/Modbus）。
14. **Group 模块**支持循环（`循环使能 / 循环起始值 / 循环结束值 / 循环间隔(ms) / 中断循环`），并用「累积输出」可替代数据集合模块。
15. **数据组织四件套**：数据集合（整合循环结果）、数据筛选（条件「或」，判断「且」）、数据分类（默认「且」+ 可开启互斥）、数据排序（组合排序）。
16. **数据筛选 vs 数据分类**：前者只判定通过/不通过并输出筛选集；后者把数据分到多个分类（互斥时高优先级独占）。
17. **通信接收链路**：接收数据（数据队列/通信设备/变量管理）→ 协议解析（文本/脚本/字节）→ 后续模块。
18. **通信发送链路**：协议组装（文本/脚本）→ 发送数据（数据队列/通信设备/变量管理/视觉控制器/发送事件）；相机IO通信、发送数据(视觉控制器) 控制 IO 电平反转。
19. **协议解析/组装的 Python 脚本**（`Receive.py` / `Send.py`）属于通信专用脚本，与「脚本模块 / 全局脚本」不同，不可混用。
20. **落盘与展示**：文本保存（TXT/CSV，输入仅 string，≤4095 字节）、数据记录（int/float，供运行界面趋势图/Pie/线图订阅）、耗时统计（最多 64 个 Time*）。

## 一、采集模块

### 图像源

**功能**：为流程提供初始图像，是大多数流程的第一个模块；支持本地图像、相机、SDK 三种输入源，用于调试与现场实时采图。

**输入**：无前序模块（通常是流程首模块）。
**输出**：

| 输出项 | 类型 | 说明 |
| --- | --- | --- |
| 图像 | image | 当前图像数据（含图像宽度/高度/像素格式） |
| 图像*（\*代表1~3） | image | 分时频闪拆图输出的多张图（开启输出Mono8时仅 `图像` 输出Mono8） |
| 灰度图像 | image | 开启输出Mono8时的灰度图 |
| 当前图像路径 / 名称 | string | 图像路径与名称 |
| 帧号 / SN码 | int | 帧序号 / SN 步进累加值 |
| 丢帧数 / 丢包数 / 相机获取失败次数 | int | 相机采图统计 |

**参数**：

| 参数名 | 取值范围 / 选项 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 像素格式（本地图像） | MONO8 / RGB24 | — | 黑白图选 MONO8，彩色图选 RGB24 |
| 方案存图 | 开 / 关 | 关 | 开启后保存方案时一并保存本地图（最多 120 张） |
| 显示图像名称 | 开 / 关 | — | 在图像显示区左下角显示名称 |
| SN初始值 | 自定义数值 / 订阅 | — | 首张图帧号，后续步进 1 |
| 图像缓存 | int | — | 本地图内存缓存数量，最多 5 张 |
| 输出Mono8 | 开 / 关 | — | RGB24 时开启，额外输出灰度图 |
| 拼接使能 | 开 / 关 | 关 | 启用 Y 方向拼接上一张缓存图 |
| 起始高度 | 0 ~ 20000 | — | 上一张缓存图裁剪起点（起始+拼接高度 ≤ 原图高） |
| 拼接高度 | 0 ~ 20000 | — | 上一张缓存图拼接高度 |
| 触发清空 | 开 / 关 | — | 订阅触发变量非 0 时清空缓存 |
| 触发变量 | 订阅 | — | 一般订阅全局/局部变量或前序流程输出 |
| 自动切换 | 开 / 关 | — | 每次重跑自动切下一张本地图 |
| 最后一张停止 | 开 / 关 | — | 连跑完最后一张后自动停止 |
| 字符触发过滤 | 开 / 关 | — | 外部通信控制是否运行 |
| 输入字符 / 触发字符 | string | — | 仅匹配触发字符才触发（空=任意字符触发） |
| 订阅图片文件夹 | 开 / 关 | — | 从订阅文件夹取图 |
| 图像路径 / 更新缩略图 / 触发流程执行 | — | — | 文件夹路径、缩略图刷新、增减即触发 |
| 关联相机（相机模式） | 下拉选择 | — | 选择已配置全局相机 |
| 控制曝光 / 控制增益 | 订阅（float） | — | 配合脚本或其他模块输出控制相机 |
| 控制曝光/增益（SDK同相机） | — | — | 同相机参数项 |

**使用步骤**：
1. 拖入图像源，双击打开参数；选择图像源类型（本地图像 / 相机 / SDK）。
2. 本地图像：设置像素格式、方案存图、SN初始值、图像缓存；如需拼接设「拼接使能」及起止高度。
3. 相机：先通过相机管理添加全局相机，再「关联相机」；可设控制曝光/增益、字符触发过滤。
4. 调试用「自动切换 / 最后一张停止」控制连续跑图行为。

**应用示例 / 注意事项**：图像过曝/过暗/模糊会显著降低方案精度；环境光变化大时建议遮光或调光源。相机曝光可自动/手动；智能相机仅在 X86 智能相机/开放平台使用。

### 多图采集

**功能**：获取多张本地图像，或通过相机+光源拍摄不同角度/亮度多图，主要搭配多图融合模块。

**输入**：无（流程首模块）。
**输出**：

| 输出项 | 类型 | 说明 |
| --- | --- | --- |
| 输出图像数据.图像数量 | int | 3~8 张 |
| 输出图像*（\*代表0~7） | image | 每张图含宽度/高度/格式/分布角/照射角 |
| 帧号 / 丢帧数 / 丢包数 / 相机获取失败次数 | int | 相机统计 |

**参数**：

| 参数名 | 取值范围 / 选项 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 取图数量（本地图像） | 3 ~ 8 | — | 最少 3 张，最多 8 张 |
| 图像路径（本地图像） | 路径 | — | 选择本地图像文件夹 |
| 分布角（本地/相机） | float（角度） | — | 0°=右侧入射，90°=顶部，180°=左侧 |
| 照射角（本地/相机） | float（角度） | — | 相机光轴与入射光线夹角 |
| 关联相机（相机） | 下拉 | — | 选择全局相机 |
| 取图间隔（相机） | ms | — | 相邻两次取图时间间隔 |
| 相机曝光（相机） | float | — | 优先调曝光提亮 |
| 相机增益（相机） | float | — | 曝光明暗不足时辅助提亮（噪声随增益增大） |
| 光源设备（相机） | 下拉 | — | 控制管理器已添加的光源设备 |
| 触发时间（相机） | ms | — | 光源触发后持续点亮时间 |
| 光源通道 / 光源亮度（相机） | 通道 + 0~255 | — | 对应通道亮度 |

**使用步骤**：
1. 拖入多图采集，选「本地图像」或「相机」。
2. 本地图像：设取图数量（3~8），按数量配置多组「图像配置n」（分布角/照射角模拟打光）。
3. 相机：先建全局相机与光源设备；设取图间隔、各图像配置的曝光/增益/光源通道亮度。

**应用示例 / 注意事项**：输出图数量与图像配置组数一致；多图融合模块对 3~8 张不同光图融合。图像质量注意事项同图像源。

### 输出图像

**功能**：对全局相机/本地/处理过的图像进行显示与存储；可触发保存、FTP 上传、渲染文本/前序结果。

**输入**：前序图像（输入源订阅）。
**输出**：

| 输出项 | 类型 | 说明 |
| --- | --- | --- |
| 模块状态 | int | 0=NG / 1=OK |
| 本地原图/渲染图保存路径、原图/渲染图名称 | string | 存图路径与文件名 |
| 大文件路径 | string | 开启大文件存图时可用 |
| 输出图像 | binary | 输出图像二进制（宽/高/像素格式） |

**参数**：

| 参数名 | 取值范围 / 选项 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 输入源 | 下拉 | — | 方案图像源图或其他模块处理结果 |
| 输出使能 | 开 / 关 | — | 关时不出图，省耗时 |
| 存图使能 | 开 / 关 | 关 | 开启后同时存图 |
| 触发保存 | 开 / 关 | 关 | 开启后按条件存图 |
| 触发变量 | 订阅 | — | 一般绑条件检测结果 |
| 保存条件 | 全部保存 / OK时保存 / NG时保存 / 不保存 | — | OK/NG 时文件名含对应字符 |
| 生成目录 | 开 / 关 | — | 按 月/日 建文件夹 |
| 存图间隔 | ≤10 张 | — | 触发存图缓存张数（≤图像缓存队列上限） |
| 保存渲染图/原图 | 开 / 关 | — | 路径最大长度 255（Windows 限制 260） |
| 渲染图/原图命名 | 自定义 + 序号/时间/无 | — | 前半部分必填，否则存图失败 |
| 渲染图/原图缓存 | ≤20 张 | — | 缓存队列上限 |
| 存储方式 | 覆盖存储 / 停止存储 | — | 达上限或磁盘不足时处理 |
| 磁盘剩余空间 + 存储单位 | 数值 + MB/GB | — | 低于设定值尝试删旧图 |
| 最大保存天数 | ≤500 天 | — | 自动删除过期图 |
| 保存格式 | BMP / JPEG / PNG | — | JPEG 可设压缩质量 |
| 图片压缩质量 | 0~100（越大越好） | — | 仅 JPEG |
| 启用FTP | 开 / 关 | — | 服务器IP/端口/用户名/密码/编码格式/FTP路径 |
| 像素格式 | RGB24 / MONO8 | — | — |
| 图形倍率类型 | 原图尺寸 / 界面尺寸 / 自定义倍率 | — | 自定义倍率含线宽倍率/字宽倍率 |
| 线型 | 4连通线 / 8连通线 / 抗锯齿线 | — | 渲染线型 |
| 渲染设置.内容 / 颜色 / 字号 / 位置X-Y | — | — | 渲染文本信息与位置 |
| 前项存储设置 | — | — | 订阅前序模块结果显示到输出图 |

**使用步骤**：
1. 拖入输出图像，设输入源。
2. 存图：开「存图使能」→「触发保存」+「保存条件」+「保存渲染图/原图」及路径命名。
3. FTP：填服务器参数并「连接」校验；本地缓存图自动上传后删除。
4. 渲染：设图形倍率类型、线型、渲染文本内容/颜色/字号/位置，订阅前项存储显示。

**应用示例 / 注意事项**：Windows 路径长度 ≤255，超出存图失败；FTP 失败无提示、图留本地。

### 缓存图像

**功能**：调试用，临时缓存图像（最多 15 张），便于误判样本快速重新绑定与追溯；后续模块可订阅任意一张缓存图。

**输入**：

| 输入项 | 类型 | 说明 |
| --- | --- | --- |
| 输入源 | image | 订阅前序模块输出图像 |

**输出**：

| 输出项 | 类型 | 说明 |
| --- | --- | --- |
| 模块状态 | int | 0=NG / 1=OK |
| 输出图像*（\*代表0~14） | image | 每张图宽/高/格式（Mono8=17301505, RGB24=35127316） |

**参数**：

| 参数名 | 取值范围 / 选项 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 缓存使能 | 0 / 1 | 1（无绑定时） | 0=不使能，1=使能；仅限 int 订阅 |
| 缓存数量 | int（≤15） | — | 缓存图片数量，可自定义或绑定 |

**使用步骤**：
1. 拖入缓存图像，订阅前序图像为输入源。
2. 设缓存使能与缓存数量；流程运行一次缓存一张，存满按时间覆盖最早一张。

**应用示例 / 注意事项**：覆盖逻辑——最新图从下方进入，最早图被顶替；下游可绑定 0~14 任意一张。

### 光源

**功能**：控制/调节现场照明（常亮或频闪），由前序模块 OK/NG 状态或触发字符驱动。

**输入**：前序模块状态/触发字符（输入类型：输入 / 订阅）。
**输出**：

| 输出项 | 类型 | 说明 |
| --- | --- | --- |
| 通道*使能（\*1~6） | bool | true=使能 |
| 通道*亮度（\*1~6） | int | 0~100（视觉控制器）/ 0~255（光源控制器） |
| 通道*光源状态（\*1~4） | int | 1=常灭触发亮，2=常亮触发灭 |
| 通道*沿定义（\*1~4） | int | 1=上升沿，2=下降沿 |
| 通道*持续时间（\*1~4） | int | 0~65535 |
| 模块状态 | int | 0=NG / 1=OK |

**参数**：

| 参数名 | 取值范围 / 选项 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 光源设备 | 下拉 | — | 关联已建光源设备 |
| 输出类型 | OK时输出 / NG时输出 | — | 前序状态触发光源 |
| 触发字符 | OK / NG | — | 须与输出类型一致，否则不触发 |
| 触发时间(ms) | -1 ~ 65535 | — | -1=常亮；>0=频闪。触发间隔内勿二次触发 |
| 输入类型 | 输入 / 订阅 | — | — |
| 通道*使能 | 开 / 关 | — | 对应通道使能（数量由设备决定） |
| 通道*亮度 | 0~100 / 0~255 | — | 0=关，越大越亮 |
| 光源状态* | 常亮 / 常灭 | — | 仅部分设备可设（VC2000/VC3000 Light板/VC3000H-X/VC4000/VB2200/VB2230） |
| 通道*沿定义 | 上升沿 / 下降沿 | — | 仅 Light板/VC3000H-X/VC4000 |
| 持续时间(ms) | 0~65535 | — | 触发后亮/灭持续时长 |

**使用步骤**：
1. 先通过控制器管理建立并连接光源设备。
2. 拖入光源，关联光源设备，设输出类型/触发字符。
3. 设触发时间；开启各通道使能与亮度；按设备能力设光源状态/沿定义/持续时间。

**应用示例 / 注意事项**：VC3000、VC3000(IO扩展板)、VT2000、VT3000 不支持接入光源模块。

## 二、拆分组合模块

### 划片拆分

**功能**：将检测区域按行/列划成多个划片矩形，供拷贝填充、Group 等逐个处理（如阵列相似图形拆分）。公式：`S*M-(M-1)*F*L = L`（S=划片长，M=划片数，F=重叠率，L=检测区长）。

**输入**：前序图像/ROI（基本参数、结果显示同常规模块）。
**输出**：

| 输出项 | 类型 | 说明 |
| --- | --- | --- |
| 检测区域 | box | ROI（中心点X/Y、宽/高/角度） |
| 分片矩形 | float[] | 每个分片中心X/Y、宽/高/角度 |
| 划片个数 | int | 总划片数 |

**参数**：

| 参数名 | 取值范围 / 选项 | 默认值 | 说明 |
| --- | --- | --- | --- |
| X方向划片数 | int | — | 水平方向划片数量 |
| Y方向划片数 | int | — | 垂直方向划片数量 |
| X方向重叠率 | 0~1 | 0 | 0=无重叠 |
| Y方向重叠率 | 0~1 | 0 | 0=无重叠 |

**使用步骤**：设 X/Y 方向划片数与重叠率；常与拷贝填充、Group 配合。
**应用示例**：一张图拆 3×3 = 9 区域，Group 内逐片处理。

---

### 二维阵列

**功能**：修正二维阵列初定位结果（补齐漏定位/误定位），并计算每行最小包围 Box。

**输入**：前序匹配/目标检测等（含中心点）。
**输出**：

| 输出项 | 类型 | 说明 |
| --- | --- | --- |
| 修正匹配框个数 | int | 修正后框数 |

**示例**：快速匹配输出匹配点 X/Y，按 X 升序排序输出（`moduleVar.in0/in1` 读、`moduleVar.out0/out1` 写，异常 `PrintMsg(e)`）。

#### 数据分类

| IO*输出条件 | 订阅/自定义（OK/NG） | — | 仅支持 OK/NG；相机类型决定 IO 数：普通相机 2、线阵 4、智能相机 3 |
| 关联相机 | 下拉（全局相机） | — | 相机管理中的全局相机 |
| 相机类型 | 普通相机/线阵相机/智能相机 | — | 普通/线阵需设持续时间；智能相机仅 X86 智能相机/开放平台 |
| 持续时间使能 | 开 / 关 | — | 开启设持续时间(ms)控制电平时长；未开则直接反转至下次满足再反转 |

**使用步骤**：关联相机→设相机类型→IO*输出条件订阅 OK/NG→设输出类型与持续时间。

## 五、横向对比与选型

### 脚本 vs Python脚本 怎么选
| 维度 | 脚本（C#） | Python脚本（Python） |
| --- | --- | --- |
| 语言 | 标准 C#（Windows） | Python |
| 变量类型 | 含 `int[]/float[]/...[]` 数组及 ROIBOX/ANNULUS/POLYGON/FIXTURE 等 | 同类型，数组写作 `[]`；结构体字段见上 |
| 核心方法 | `Init`（初始化）+ `Process` | 仅 `Process(data)`，进函数先 `IoHelper(data, INIT_*)` 初始化 |
| 变量读写 | 变量名直读 `in0`/直写 `out0`；或 `Get/Set*` 老接口 | `moduleVar.in0` 读、`moduleVar.out0=9` 写；全局/局部用 `globalVar/localVar` |
| 通信/模块控制 | 完整：`GlobalCommunicateModule`、`CurrentProcess.GetModule`、`ShowImage/DrawShape` 等 | 仅 globalVar/localVar 的 Get/Set，无直接通信/渲染接口 |
| 调试 | 可导出工程用 VS 附加调试 | 无 VS 调试，靠 `PrintMsg` 打印 |
| 加密狗限制 | `ShowImage/DrawShape` 需 6210/7120 | 无此限制说明 |
| 缩进 | C# 大括号 | 严格 4 空格，禁 tab |

**建议**：需要直接操控通信发送、读写任意模块参数、渲染图像/图形 → 用 C# 脚本；只需流程内数据变换（排序、计算、格式整理）且团队熟 Python → 用 Python脚本。两者都只处理流程内数据，跨流程批量逻辑走全局脚本。

### 接收数据 vs 通信管理（通信设备）怎么分工
- **通信管理**：在 VM 主界面配置通信设备（TCP/UDP/串口/PLC/Modbus），是「设备通道」层。
- **接收数据模块**：流程内「取数」动作，数据源选「通信设备/数据队列/变量管理」；收到的一般是 PLC 的 16 进制组装结果，需接**协议解析**拆成可用数据。
- 即：通信管理建通道 → 接收数据取数 → 协议解析拆解 → 后续模块；反向：协议组装 → 发送数据 → 通信设备发出。

### 数据筛选 vs 数据分类 区别
| 维度 | 数据筛选 | 数据分类 |
| --- | --- | --- |
| 目的 | 判定通过/不通过，输出筛选集 | 把数据分到多个命名分类 |
| 默认逻辑 | 条件间「或」，判断间「且」 | 默认「且」；可开「互斥」 |
| 重叠处理 | 满足任一条件即输出 | 条件可重叠；开互斥后高优先级分类独占（列表上→下优先级降） |
| 输出 | 数据个数 + 筛选后参数 | 各分类相关参数 |
| 典型用 | 只保留合格项 | 按个数/面积分 A/B/C 档 |

### 其他易混点
- **分支模块（int）vs 分支字符（string）**：整数走分支模块（支持按值/按位索引）；字符串走分支字符（OK/NG）。
- **条件分支 vs 条件检测**：条件检测只出 OK/NG 结果；条件分支用该结果决定「执行哪条后序模块」。
- **数据集合 vs Group 累积输出**：两者都能整合循环结果，同用易错，推荐二选一（Group 累积输出更简洁）。
- **输出图像 vs 缓存图像**：前者落盘/上传/渲染；后者仅内存缓存 ≤15 张用于调试回溯，不落盘。
- **Box融合 vs Box过滤**：融合=合并重叠 Box；过滤=按掩膜 255 占比剔除不达标的 Box（推荐在多标签筛选后）。
